# 規則の理由

素の`preset`をそのまま当てると、日本語の技術文書と噛み合わない指摘が出る。
切った規則、ゆるめた規則には、なぜそうしたかを必ず書く。
理由の書けない除外を増やさないためである。

## 前提としている書き方

この設定は、次の書き方を前提にしている。
違う書き方をする場合は、対応する規則を上書きすればよい（README「設定を変える」）。

- 文体は「である調」で統一する。ですます調に切り替えられる
- 一文一行で書く。1行に2文を書かない
- 長い1文を途中で折り返すことは許す
- 表の列幅はエディタが自動でそろえる

## Markdownの規則

`config/markdownlint.jsonc`にある。
既定を土台にし、噛み合わない規則だけを切ってある。

| 規則 | 設定 | 理由 |
| ---- | ---- | ---- |
| MD013 | 切る | 一文一行で書くと、一文が80文字を超えることは普通にある。日本語は文字数と表示幅も一致しないため、行長で測ること自体が噛み合わない |
| MD024 | `siblings_only` | 番号や識別子で区別する見出し（「3.9. 一覧（S09）」と「3.14. 一覧（S15）」）がある。兄弟の見出しどうしだけを見る |
| MD029 | `one` | 順序付きリストはすべて「1.」で書く。順番を入れ替えても差分が1行で済む |
| MD046 | `fenced` | コードブロックはフェンスに統一する |
| MD048 | `backtick` | コードフェンスの記号はバッククォートに統一する |
| MD049 | `asterisk` | 強調の記号はアスタリスクに統一する |
| MD050 | `asterisk` | 太字の記号も同じ |
| MD060 | 切る | 表の記号の揃え方を1つに求める規則である。日本語の表は全角と半角が混ざり、エディタによって「そろっている」の意味が変わる。有効にすると、表を1行足すたびに列幅の付け直しを迫られ、差分が本文以外で膨らむ |

上に無い規則は既定のままである。
生のHTML（MD033）と裸のURL（MD034）も既定どおり禁じている。

## 日本語の規則

`config/textlint-base.js`にある。
3つの`preset`を土台にしている。

### 検査を止めるもの

| 規則 | 設定 | 理由 |
| ---- | ---- | ---- |
| `no-mix-dearu-desumasu` | である調 | `preset`の既定は「ですます」なので入れ替える。ですます調も選べる |
| `sentence-length` | 120文字 | 一文一行で書くと一文が長くなり、既定の100文字では収まらない文がある |
| `ja-no-mixed-period` | 切る | 「最終更新: 2026-09-04」のような、文ではない行を文とみなして指摘する。文末の体裁は`no-mix-dearu-desumasu`が実質的に見ている |
| `4.2.6.ハイフン(-)` | 切る | 「A-B-C」のようなキーや識別子の書式に使う |
| `4.2.7.コロン(：)` | 切る | 「最終更新: 2026-09-04」の形を見出しや前書きで使う |
| `3.3.かっこ類と隣接する文字の間のスペースの有無` | 切る | 下の「箇条書きを壊す規則」を見よ |
| `ja-no-space-around-parentheses` | 切る | 同上 |

### 警告として出すもの

直す価値はあるが、検査を止めるほどではないものである。
`textlint`は`error`だけで終了コードを1にするため、警告は検査を通しつつ目に入る。

| 規則 | 見るもの |
| ---- | ---- |
| `no-doubled-joshi` | 助詞の連続 |
| `max-kanji-continuous-len` | 漢字の連続。既定は6文字まで。仕様の用語や固有名詞は言い換えられないことがある |
| `ja-no-redundant-expression` | 冗長な表現 |
| `ja-unnatural-alphabet` | 不自然なアルファベット |

## 箇条書きを壊す規則

`3.3.かっこ類と隣接する文字の間のスペースの有無`と`ja-no-space-around-parentheses`を切っているのは、
体裁の好みではなく、`--fix`が文書の構造を壊すためである。

箇条書きの続きの行は、2つのスペースで字下げする。
その行が全角のかっこ（`（`や`」`）で始まると、この2つの規則は字下げをかっこの前のスペースとみなして指摘する。
さらに`--fix`をかけると字下げが削られ、続きの行が別の段落になる。

切っていない場合でも、`--fix`をかけたあとは差分を見るのが安全である。

## 意外と引っかかる規則

全角と半角の間にスペースを入れないことを求める規則は、既定で有効にしてある。

```text
正規表現は JavaScript のものである。   ← 指摘される
正規表現はJavaScriptのものである。     ← 通る
```

半角の語をコードスパンに入れれば、前後のスペースは指摘されない。

```text
規則は`markdownlint-cli2`が読む。      ← 通る
```

表の中も指摘されない。
半角の語が多い文は、コードスパンに入れるか表に置くと読みやすさを保てる。

この規則は2つある。
`preset-ja-spacing`の`ja-space-between-half-and-full-width`と、
`preset-jtf-style`の`3.1.1.全角文字と半角文字の間`である。
片方だけを切っても、もう片方が同じ指摘を出す。

`halfWidthSpacing`はこの2つをまとめて扱う。

| 設定 | `これは JavaScript の文` | `これはJavaScriptの文` |
| ---- | ---- | ---- |
| `'never'`（既定） | 指摘される | 通る |
| `'always'` | 通る | 指摘される |
| `false` | 通る | 通る |

## 規則を上書きする

利用側で個別に変えられる。
書き方はREADMEの「設定を変える」にある。

上書きするときは、なぜ変えたかをその場に書くとよい。
理由の書けない除外が増えると、規則そのものが形骸化する。
