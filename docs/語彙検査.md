# 語彙検査

`lint-vocabulary` は、禁じた語彙がソースに混入していないかを見る道具である。

## 何のためのものか

「この判定はこの層に置く」「この呼び出しはここでは使わない」といった取り決めは、型では表せない。
規約として文書に書いても、書いた本人が忘れる。
この道具は、そうした取り決めを禁じた語彙の有無として機械的に見る。

これは語彙の検査であって、値の行き先を追うものではない。
書き方を変えれば通ってしまうし、通ったからといって違反が無いことにはならない。
それでも、目視では見落とす混入を拾う。

## 使い方

```bash
npx lint-vocabulary
npx lint-vocabulary --config path/to/config.json
npx lint-vocabulary --format json
```

違反が無いときはこう出る。

```text
語彙の検査: 問題ありません（12件を検査）
```

違反があるときはこう出る。

```text
src/ui/CounterView.ts:9  LINT001 日付の生成と計算は中核層に置く。
    const label = new Date(now).toLocaleDateString('ja-JP')

禁じた語彙が1件見つかりました（12件を検査）。
表示や記録のためだけに要る行は、その行か直前の行に理由を添えて断ってください（例: 検査除外: 理由）。
```

設定ファイルを省略すると、現在のディレクトリから次の順に探す。

1. `lint-vocabulary.config.json`
1. `lint-vocabulary.config.jsonc`
1. `.lint-vocabularyrc.json`

## 設定

```jsonc
{
  // 断りの語。省略すると「検査除外」になる
  "allowMarker": "検査除外",

  "targets": [
    {
      // 出力に出る名前。省略すると path を使う
      "name": "画面層",

      // 対象のディレクトリ。設定ファイルからの相対で解釈する
      "path": "src/ui",

      // 見る拡張子。空か省略ならすべてのファイルを見る
      "extensions": [".ts", ".tsx"],

      // 見ないもの。* は1階層、** は複数階層に当たる
      "exclude": ["**/*.test.ts"],

      // true にすると、対象が無くても止めずに飛ばす
      "optional": false,

      "rules": [
        {
          // 出力に出る記号
          "code": "LINT001",

          // JavaScript の正規表現。行ごとに当てる
          "pattern": "new Date\\(|\\.getTime\\(",

          // 引っかかったときに出す文言。どこへ移すかを書く
          "message": "日付の生成と計算は中核層に置く。"
        }
      ]
    }
  ]
}
```

`allowMarker` は対象ごとに上書きできる。
`rules` の `flags` に `i` `m` `s` `u` を指定できる。
`g` は指定しない。行ごとに当てるため、指定しても意味が無いうえ取りこぼしを生むためである。

正規表現はJavaScriptのものである。
`[[:space:]]` のようなPOSIXの文字クラスは使えない。
書いてしまった場合は、黙って一致しなくなるのではなく、設定の誤りとして止まる。

## 断り

表示のためだけに要る行など、規則に当たるが問題の無い行がある。
その行か直前の行に、理由を添えて断る。

```typescript
// 検査除外: 表示している日付を出すだけで、記録の可否には関わらない
const label = new Date(now).toLocaleDateString('ja-JP')
```

同じ行に書いてもよい。

```typescript
const label = new Date(now).toLocaleDateString('ja-JP') // 検査除外: 表示するだけである
```

断りの書式は、語のあとにコロンと理由である。
コロンは半角と全角のどちらでもよい。
コメントの記号は問わない。
`//` でも `#` でも `--` でも通る。言語によって書き方が分かれるためである。

理由の無い断りは通らない。

```typescript
// 検査除外:
const label = new Date(now).toLocaleDateString('ja-JP')
```

断りが効くのは、その行と直後の行だけである。
1つの断りで広い範囲を黙らせることはできない。
広い範囲を除きたい場合は `exclude` を使う。

## 終了コード

| コード | 意味 |
| ---- | ---- |
| 0 | 違反なし |
| 1 | 違反あり |
| 2 | 設定の誤り、対象が無い、読めないものがある、1件も検査できなかった |

CIでは1と2のどちらも失敗として扱えばよい。

## 検査していないものを成功と数えない

この道具のいちばんの害は、検査していないものを「問題なし」と報告することである。
そうならないよう、次のようにしてある。

- 何件を検査したかを必ず出す
- 1件も検査できなかったら終了コード2で止める。
  `path`や`extensions`や`exclude`の書き間違いは、ここで気付ける。
  空でよい対象には`optional: true`を書く
- 読めないファイルやディレクトリがあれば終了コード2で止める。
  飛ばして0を返すと、検査したつもりのまま通ってしまう
- 飛ばしたファイルは標準エラーに理由つきで出す

## 見ないもの

次のものは常に飛ばす。
飛ばしたものは黙って落とさず、標準エラーに理由を出す。

| 対象 | 理由 |
| ---- | ---- |
| `node_modules`、`.git`、`.hg`、`.svn` | 自分で書いたものではない |
| シンボリックリンク | 辿ると対象の外へ出てしまい、同じファイルを二度見ることがある |
| NUL文字を含むファイル | 文字として読めない。生成物とみなす |
| 2 MiBを超えるファイル | 同じく生成物とみなす |
| UTF-8として読めないファイル | Shift-JISやEUC-JPのソースがこれに当たる。そのまま検査すると規則も断りも当たらず、静かに素通りする |

UTF-8でないソースを検査したい場合は、文字コードを変換してから通す。

## 限界

知っておくべき限界が3つある。

1つ目は、語彙の検査であることそのものである。
`new Date(` を禁じても、`Date["now"]()` と書けば通る。
抜け道を塞ぐ道具ではなく、うっかりを拾う道具である。

2つ目は、断りが文字列リテラルの中にあっても効いてしまうことである。
`const s = "検査除外: これは文字列である"` と書かれた行は見逃される。
構文解析をしないため、コメントと文字列を区別できない。

3つ目は、規則が行をまたげないことである。
1行に1回ずつ当てるため、2行に分かれた式は捕まえられない。
